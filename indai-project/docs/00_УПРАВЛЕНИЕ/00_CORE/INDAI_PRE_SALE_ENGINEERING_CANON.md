## 0. Роль документа в системе

Данный документ фиксирует **инженерную природу пресейла INDAI**.

Он определяет:
- что считается лидом,
- когда допустима цена,
- на чём основано КП,
- где INDAI обязана отказаться,
- как устроена последовательность пресейла.

Документ **НЕ описывает** формы, CRM, автоматизации или интерфейсы.  
Он задаёт **логику**, которой обязаны подчиняться все операционные протоколы.

## 2. Базовый принцип (неизменяемый)

> **INDAI не продаёт услуги.  
> INDAI валидирует объект и продаёт подтверждённый результат.**

### 2.1 Определение лида

**Лид INDAI — это не контакт.**  
**Лид INDAI — это объект, прошедший инженерную валидацию.**

| Что является лидом | Что НЕ является лидом |
|---|---|
| Объект с описанием задачи, прошедший хотя бы этап 1 (консультацию) | Телефон / email без контекста объекта |
| Объект, для которого определена применимость методов INDAI | Запрос «сколько стоит очистка?» без данных |
| Объект с зафиксированным инженерным контекстом | Заявка из формы «перезвоните мне» |

### 2.2 Следствие

Любой процесс, который:
- считает контакт = лидом,
- формирует КП без валидации объекта,
- называет цену без инженерного теста,

**считается архитектурно неверным**, даже если приносит выручку.

## 3. Pre-Sale Value Ladder (канон)

### 3.1 Последовательность этапов

Единственная допустимая последовательность:

| Этап | Название | Результат этапа | Условие перехода к следующему | Ответственный |
|---|---|---|---|---|
| 1 | **Консультация** | Описание объекта и задачи зафиксировано | Задача попадает в зону применимости INDAI | Инженер / AI-ассистент |
| 2 | **Осмотр / диагностика** | Инженерный отчёт о состоянии объекта | Объект физически доступен; метод потенциально применим | Инженер (выезд) |
| 3 | **Инженерный тест** | Протокол теста: результат + ось ценности + scope | Тест положительный (см. §4) | Инженер |
| 4 | **Коммерческое предложение** | КП с обоснованием: ось + scope + цена + условия | Клиент согласует условия | Коммерция + инженер |
| 5 | **Контракт** | Подписанный договор | Юридическое согласование | Коммерция |
| 6 | **Долгосрочное сопровождение** | Регламент обслуживания / консалтинговый контракт | Успешное выполнение первого контракта | Инженер + коммерция |

### 3.2 Жёсткие запреты

- **Перескакивать этапы** — запрещено
- **Называть цену** до этапа 3 (инженерный тест) — запрещено
- **Формировать КП** без протокола теста — запрещено
- **Подписывать контракт** без КП — запрещено

### 3.3 Связь с сайтом

| Элемент сайта | Этап Value Ladder |
|---|---|
| CTA «Описать объект» / «Обсудить задачу» | → Вход в этап 1 |
| AI-ассистент на HomePage / Service Page | → Этап 1 (консультация, определение применимости) |
| Форма описания объекта (если существует) | → Этап 1 (сбор данных) |

AI-ассистент **не может** перевести пользователя дальше этапа 1 без участия инженера.

## 4. Инженерный тест — ядро системы

### 4.1 Определение

Инженерный тест — это **не** демонстрация и **не** пресейл-ритуал.

Инженерный тест — это:
- проверка применимости технологии к конкретному объекту,
- замер доминирующей оси ценности (§5),
- основание для расчёта scope и цены,
- точка принятия решения INDAI: работаем или отказываемся.

### 4.2 Кто проводит

Инженер INDAI с квалификацией, достаточной для:
- оценки состояния объекта,
- выбора метода,
- фиксации результата теста.

**Не проводят:** менеджеры по продажам, AI-ассистент, подрядчики без допуска.

### 4.3 Формат результата

Результат инженерного теста фиксируется в **протоколе**, содержащем:

| Поле | Обязательность |
|---|---|
| Идентификация объекта (тип, расположение, параметры) | Обязательно |
| Описание задачи | Обязательно |
| Применённый метод теста | Обязательно |
| Результат теста (фактический) | Обязательно |
| Фото/видео до и после теста | Обязательно |
| Определённая ось ценности (§5) | Обязательно |
| Рекомендуемый scope работ | Обязательно |
| Ограничения / риски | Обязательно |
| Вердикт: PASS / FAIL / CONDITIONAL | Обязательно |
| Подпись инженера | Обязательно |

### 4.4 Вердикты теста

| Вердикт | Значение | Следующее действие |
|---|---|---|
| **PASS** | Метод применим, результат достижим | → Этап 4 (КП) |
| **CONDITIONAL** | Метод применим с ограничениями | → КП с фиксацией условий и рисков |
| **FAIL** | Метод неприменим или риски неприемлемы | → Отказ (§7) |

### 4.5 Принцип

> **Без инженерного теста коммерческое предложение не существует.**

## 5. Оси ценности (канон)

### 5.1 Определение

Для каждого объекта **обязательно** определяется **одна** доминирующая ось ценности — главный параметр, по которому оценивается ценность работы для клиента.

### 5.2 Канонические оси

| Ось | Определение | Пример контекста |
|---|---|---|
| **Скорость** | Минимизация времени простоя оборудования | Аварийный останов; плановый ремонт с жёстким окном |
| **Качество** | Максимальная глубина/полнота результата | Подготовка к инспекции; восстановление проектных параметров |
| **Безопасность** | Минимизация рисков при выполнении работ | Взрывоопасные среды; работа на действующем объекте; требования HSE |
| **Технологическая уникальность** | Применение метода, недоступного альтернативными способами | Объект недоступен для стандартных методов; уникальная геометрия; специфические отложения |

### 5.3 Правила

- Ось определяется **на этапе 3** (инженерный тест) или раньше (если очевидна на этапе 2)
- Ось фиксируется в **протоколе теста** (§4.3)
- Ось определяет **логику цены и аргументации** КП
- **Несколько доминирующих осей одновременно — запрещено**. Вторичные оси могут упоминаться, но одна доминирует
- Ось **может смениться** только при получении новых данных об объекте. Смена фиксируется в протоколе

## 6. Принцип ценообразования

### 6.1 Основание цены

Цена INDAI выводится из:
- факта инженерного теста (§4),
- выбранной оси ценности (§5),
- scope работ,
- условий выполнения (доступность, логистика, сроки),
- инженерных рисков.

### 6.2 Абсолютный запрет

> **Прайса «по умолчанию» не существует.**  
> **Любая цена без теста — не является ценой INDAI.**

### 6.3 Позиция по ориентировочным ценам

| Ситуация | Допустимость | Формулировка |
|---|---|---|
| Клиент спрашивает «сколько стоит?» до теста | ❌ Конкретная цена запрещена | — |
| Клиент спрашивает «какой порядок цен?» | ⚠️ Допустимо с оговоркой | «Стоимость определяется по результатам инженерного теста. Порядок для задач этого класса — [диапазон], но финальная цена зависит от параметров объекта» |
| AI-ассистент получает вопрос о цене | ❌ Конкретная цена запрещена | AI объясняет логику: «Цена формируется после обследования объекта и инженерного теста» |
| Сайт (любая страница) | ❌ Цены запрещены | См. Services Pages Canon §6.10, Implementation Rules §4.5 |

### 6.4 Принцип

> **Цена — результат инженерной работы, а не маркетингового решения.**

## 7. Принцип отказа (инженерная ответственность)

### 7.1 Когда INDAI обязана отказаться

- Метод неприменим к данному объекту
- Риски превышают допустимые
- Результат не может быть подтверждён
- Объект не соответствует зоне ответственности INDAI
- Клиент требует работу без теста / без обследования

### 7.2 Формат отказа

Отказ фиксируется **письменно** и содержит:

| Поле | Обязательность |
|---|---|
| Идентификация объекта | Обязательно |
| Причина отказа (инженерная) | Обязательно |
| Ссылка на протокол теста (если тест проводился) | Если применимо |
| Рекомендация (если возможна): альтернативный метод, другой подрядчик, дополнительное обследование | Рекомендуется |
| Подпись инженера | Обязательно |

### 7.3 Тон отказа

- Честный, без маскировки маркетингом
- Без оценки клиента или его задачи
- Без попытки «удержать» через альтернативное предложение, если оно не обосновано инженерно
- Уважительный: отказ = проявление инженерной зрелости, а не потеря сделки

### 7.4 Эталонный пример

**Допустимо:**
> «По результатам обследования установлено, что характер отложений и материал оборудования не позволяют применить гидродинамический метод без риска повреждения. Рекомендуем рассмотреть химическую промывку с привлечением профильного подрядчика.»

**Запрещено:**
> «К сожалению, мы не можем вам помочь. Но у нас есть другие услуги — посмотрите наш каталог!»

## 8. AI-ассистент в контексте пресейла

### 8.1 Роль AI в Value Ladder

AI-ассистент INDAI работает **только на этапе 1** (консультация):

| Может | Не может |
|---|---|
| Уточнять тип объекта и задачи | Проводить диагностику или тест |
| Определять, попадает ли задача в зону INDAI | Называть цену или диапазон |
| Собирать описание объекта | Формировать КП |
| Направлять к соответствующей Service Page | Обещать результат |
| Объяснять логику пресейла (зачем нужен тест) | Пропускать этапы Value Ladder |
| Фиксировать контекст для передачи инженеру | Заменять инженера на любом этапе |

### 8.2 Передача от AI к инженеру

Когда AI определил, что задача в зоне INDAI:
- AI предлагает пользователю «описать объект подробнее» или «связаться с инженером»
- AI **не запрашивает** контактные данные агрессивно (pop-up, обязательные поля)
- AI **может** предложить оставить контакт для связи с инженером — нейтрально, без давления

### 8.3 AI при вопросе о цене

AI **обязан** объяснить логику, а не отказать молча:

**Допустимо:**
> «Стоимость работ определяется после обследования объекта и инженерного теста. Это позволяет дать точную цену, основанную на реальных параметрах. Опишите объект — и мы определим применимость.»

**Запрещено:**
> «Мы не называем цены.»

## 9. Критерии приёмки (проверка процесса)

### 9.1 Проверка Value Ladder

| # | Проверка | Критерий |
|---|---|---|
| V1 | Каждое КП имеет привязку к протоколу теста? | Если нет → КП недействительно |
| V2 | В протоколе теста указана ось ценности? | Если нет → протокол неполон |
| V3 | Цена в КП выведена из scope + ось + условия? | Если нет → цена необоснована |
| V4 | Были ли случаи перескакивания этапов? | Если да → нарушение §3.2 |
| V5 | Отказы оформлены письменно с причиной? | Если нет → нарушение §7.2 |

### 9.2 Проверка AI

| # | Проверка | Критерий |
|---|---|---|
| A1 | AI не называет конкретные цены? | Grep по логам / тест-кейс |
| A2 | AI объясняет логику при вопросе о цене (а не просто отказывает)? | Тест-кейс |
| A3 | AI не пропускает этапы Value Ladder? | Тест-кейс |
| A4 | AI не запрашивает контакты агрессивно? | Review диалогов |

### 9.3 Проверка сайта

| # | Проверка | Критерий |
|---|---|---|
| S1 | Ни одна страница не содержит цен? | Grep по DOM |
| S2 | CTA ведут к этапу 1 (описание объекта), а не к «заказу»? | Аудит CTA |
| S3 | Нет формулировок «получить КП» / «рассчитать стоимость»? | Grep по DOM |
