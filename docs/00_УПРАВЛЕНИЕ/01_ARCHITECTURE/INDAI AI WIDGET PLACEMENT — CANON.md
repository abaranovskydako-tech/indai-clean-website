## 1. Назначение документа

Данный документ фиксирует архитектурные правила размещения и поведения AI-виджета INDAI, чтобы:

- не нарушать логику восприятия HERO;
- не создавать преждевременное давление на пользователя;
- сохранить инженерный и ненавязчивый характер бренда;
- обеспечить единообразие для дизайнеров, разработчиков и AI-агентов;
- встроить AI-виджет в общую систему лидогенерации INDAI без её искажения;
- предоставить измеримые критерии корректности реализации.

Документ обязателен к соблюдению и имеет канонический статус.

---

## 2. Принципиальная роль AI-виджета

AI-виджет INDAI — это:

- инженерный инструмент диалога,
- интерфейс первичной квалификации,
- способ демонстрации подхода INDAI к решению задач.

AI-виджет **НЕ является:**

- формой захвата лида,
- агрессивным CTA,
- заменителем контента страницы,
- автономным «продающим ассистентом».

**Принцип:** Виджет демонстрирует *как INDAI думает*, а не *как INDAI продаёт*.

**Соответствие MASTER_SPEC § 8:** `assist, not dominate`.

---

## 3. Иерархия взаимодействия с пользователем

Фиксируется строгий приоритет:

```
HERO → Смысл страницы → Контент → AI-диалог → Лид-система
```

AI-виджет **никогда не опережает:**

- HERO,
- основной смысл страницы,
- понимание услуги пользователем.

**Соответствие MASTER_SPEC § 8:** `never block content; never override user intent`.

### 3.1 Взаимодействие с другими CTA

Если на странице присутствуют основные CTA (кнопки «Заказать осмотр», формы обратной связи и т.д.):

- AI-виджет **не конкурирует** с ними визуально;
- AI-виджет **не перекрывает** их;
- при одновременном открытии модалки CTA и виджета — **модалка CTA имеет приоритет**, виджет автоматически сворачивается в иконку;
- AI-виджет не дублирует функционал основных CTA.

---

## 4. Правило HERO: присутствие без инициации

### 4.1 Размещение в HERO

В HERO-блоке AI-виджет:

- **может** присутствовать визуально;
- **не должен** доминировать;
- **не должен** требовать действия;
- **не инициирует** диалог.

Допустимые формы:

- иконка / маркер «AI-инженер INDAI»;
- вторичный интерфейсный элемент;
- неактивный или минимально активный вид.

### 4.2 Запреты в HERO

В HERO **ЗАПРЕЩЕНО:**

- активные pop-up окна;
- автозапуск диалога;
- навязчивые кнопки «Задать вопрос» как главный CTA;
- формы загрузки ТЗ, фото, видео;
- любые действия, конкурирующие с HERO-текстом.

**Принцип:** Пользователь в HERO **ориентируется**, а не действует.

### 4.3 Мобильное поведение в HERO

На мобильных устройствах (viewport < 768px):

- виджет отображается **только как иконка** (не раскрытый элемент);
- иконка размещается в правом нижнем углу (floating);
- иконка **не перекрывает** HERO-текст и основной CTA;
- минимальный отступ от края экрана: 16px;
- минимальный отступ от ближайшего интерактивного элемента: 48px (touch target spacing).

## 5. Основная точка инициации диалога

Полноценное взаимодействие с AI-виджетом допускается и рекомендуется **только после смысловой ориентации пользователя**.

### 5.1 Допустимые точки инициации (привязка к секциям)

Триггеры привязываются к **конкретным секциям**, а не к процентам скролла.

| Секция | Тип триггера | Поведение |
|--------|-------------|-----------|
| После `ProcessSection` (Как мы работаем) | Первая допустимая точка | Виджет может предложить задать вопрос (subtle hint) |
| После `ServicesSection` (Услуги) | Контекстная точка | Виджет может предложить описать объект |
| После `CasesSection` (Кейсы) | Контекстная точка | Виджет может принять ТЗ, фото или видео |
| `CTASection` (финальный блок) | Финальная точка | Виджет полностью доступен |

В этих точках AI-виджет может:

- предложить задать вопрос;
- принять описание объекта;
- принять ТЗ, фото или видео;
- сопровождаться спокойным, инженерным пояснением.

### 5.2 Запрет триггера по проценту скролла

**Запрещено** использовать процент скролла страницы как единственный триггер.  
Допустимо использовать Intersection Observer на конкретные секции (см. таблицу выше).

## 6. Поведенческие сценарии

### 6.1 Разрешённые триггеры

AI-виджет может активироваться по поведенческим триггерам, если они не нарушают тон бренда.

| Триггер | Условие | Платформа |
|---------|---------|-----------|
| exit-intent | При перемещении курсора за пределы viewport | Desktop only |
| Intersection Observer на секцию | После просмотра ключевых блоков (ProcessSection, CasesSection) | Desktop + Mobile |
| Idle timeout | После 45+ секунд бездействия на странице | Desktop + Mobile |

### 6.2 Запрещённые триггеры

- автоматическое появление при загрузке страницы;
- таймеры обратного отсчёта;
- повторяющиеся всплытия;
- давление через срочность;
- exit-intent на мобильных (технически ненадёжен).

### 6.3 Лимиты показов

| Параметр | Значение |
|----------|----------|
| Максимум инициаций за сессию | **1** (одна) |
| Повторная инициация после закрытия | Запрещена в текущей сессии |
| Повторная инициация при следующем визите | Допустима (1 раз) |
| Cooldown между визитами | ≥ 24 часа |

Если пользователь **сам** открыл виджет (клик по иконке) — это не считается инициацией и не имеет лимитов.

## 7. State Machine виджета

Виджет имеет строго определённые состояния и переходы.

### 7.1 Состояния

| Состояние | Описание | Визуал |
|-----------|----------|--------|
| `hidden` | Виджет не отображается (до допустимой секции) | Невидим |
| `icon` | Свёрнутая иконка, доступна для клика | Floating icon |
| `hint` | Иконка + короткая подсказка (1 строка) | Icon + tooltip |
| `open` | Диалоговое окно развёрнуто | Chat panel |
| `active_dialog` | Пользователь ведёт диалог | Chat panel (active) |
| `handoff` | Диалог завершён, передача в лид-систему | Confirmation view |
| `dismissed` | Пользователь закрыл виджет | Невидим / минимальная иконка |
| `error` | AI-бэкенд недоступен | Fallback view |

### 7.2 Переходы

```
hidden ──[секция достигнута]──→ icon
icon ──[триггер/клик]──→ hint
icon ──[клик пользователя]──→ open
hint ──[клик]──→ open
hint ──[игнор 5 сек]──→ icon
open ──[сообщение]──→ active_dialog
active_dialog ──[исход]──→ handoff
active_dialog ──[закрытие]──→ dismissed
open ──[закрытие]──→ dismissed
dismissed ──[клик по иконке]──→ open (диалог сохранён)
* ──[AI недоступен]──→ error
error ──[восстановление]──→ предыдущее состояние
```

### 7.3 Поведение при закрытии (dismiss logic)

| Действие пользователя | Результат |
|------------------------|-----------|
| Закрыл hint (подсказку) | Виджет возвращается в `icon`. Повторный hint **запрещён** в текущей сессии. |
| Закрыл open/active_dialog | Виджет переходит в `dismissed`. Отображается **только иконка** (без hint). |
| Клик по иконке в `dismissed` | Виджет открывается в `open` с **сохранённым** диалогом. |

## 8. Persistence (сохранение состояния)

### 8.1 В рамках одной страницы

- Диалог **сохраняется** при скролле и взаимодействии со страницей.
- Закрытие и повторное открытие — диалог **не сбрасывается**.

### 8.2 Между страницами (навигация)

- При переходе на другую страницу сайта: диалог **сохраняется** (sessionStorage / React context).
- История диалога доступна при возврате.
- Состояние виджета (open/dismissed/icon) **сохраняется** между переходами.

### 8.3 Между сессиями

- Диалог **не сохраняется** между сессиями (после закрытия вкладки).
- Факт dismiss сохраняется через cooldown (§ 6.3).

---

## 9. Fallback при недоступности AI

Если AI-бэкенд недоступен (таймаут, ошибка сети, 5xx):

| Условие | Поведение |
|---------|-----------|
| Виджет в состоянии `icon` или `hidden` | Виджет **не отображается** (переход в `hidden`). |
| Виджет в состоянии `open` или `active_dialog` | Показать сообщение: *«Сервис временно недоступен. Оставьте контакт — мы свяжемся с вами.»* с полем для телефона/email. |
| Повторная проверка | Каждые 30 секунд (silent ping). При восстановлении — переход в `icon`. |

**Принцип:** Виджет не ломает страницу. Страница полностью функциональна без виджета (MASTER_SPEC § 8: `UX > AI visibility`).

## 10. Тон и язык AI-виджета

AI-виджет INDAI:

- не продаёт;
- не торопит;
- не обещает;
- не манипулирует.

### 10.1 Допустимый язык

- спокойный;
- инженерный;
- уточняющий;
- ориентированный на понимание объекта.

**Примеры допустимых фраз:**

- «Опишите объект — мы подскажем подход»
- «Какой тип загрязнения?»
- «Расскажите подробнее о системе»

### 10.2 Недопустимый язык

- «оставьте заявку»;
- «получите расчёт за 5 минут»;
- «мы лучшие»;
- любые маркетинговые клише;
- восклицательные конструкции давления.

### 10.3 Язык интерфейса

- Весь пользовательский текст виджета — **на русском языке** (SKILL.md § Critical Rules: `Russian UI`).
- Код, переменные, комментарии — **на английском** (MASTER_SPEC § 3: `Repository language: English only`).

## 11. Связь с лид-системой INDAI

AI-виджет обязан работать в рамках канона:  
**INDAI_LEAD_GENERATION & ENGINEERING PROTOCOL** (`/docs/03_PRODUCTS/`).

### 11.1 Допустимые исходы диалога

Любой диалог с AI-виджетом **должен завершаться** одним из следующих исходов:

| # | Исход | Описание | Данные для лид-системы |
|---|-------|----------|------------------------|
| 1 | Передача в консультацию | Пользователь хочет обсудить задачу с инженером | `{ type: 'consultation', object_description, contact }` |
| 2 | Предложение осмотра | Объект требует визуальной оценки | `{ type: 'inspection', object_type, location?, contact }` |
| 3 | Переход к инженерному тесту | Объект подходит для тестовой очистки | `{ type: 'test_cleaning', object_type, contamination_type, contact }` |
| 4 | Корректный отказ | Объект нецелевой для INDAI | `{ type: 'decline', reason }` — без сбора контакта |

### 11.2 Запреты

AI-виджет **не имеет права:**

- замыкать диалог на себе (бесконечная беседа без исхода);
- удерживать пользователя без перехода в систему;
- собирать контактные данные без ведома пользователя;
- передавать данные в лид-систему при исходе `decline`.

## 12. Поведение на разных типах страниц

| Тип страницы | Начальное состояние | Допустимые триггеры | Контекст AI |
|-------------|--------------------|--------------------|-------------|
| Главная (`/`) | `hidden` → `icon` после ProcessSection | § 6.1 | Общий: квалификация объекта |
| Страница услуги (`/services/*`) | `icon` (сразу, т.к. пользователь уже ориентирован) | Клик пользователя, idle 45с | Специфика услуги |
| Кейсы / Портфолио | `icon` | Клик пользователя | Сравнение с кейсами |
| Блог / Статьи | `hidden` | Не отображается | — |
| Контакты | `hidden` | Не отображается (есть прямые формы) | — |
| 404 / Ошибка | `hidden` | Не отображается | — |

**Принцип:** На страницах с прямым контактным функционалом (формы, телефоны) виджет не дублирует их и не отображается.

## 13. Visual Layer Stack (z-index)

| Элемент | z-index | Приоритет |
|---------|---------|-----------|
| Cookie-бар | 9999 | Высший |
| Модальные окна (формы, CTA) | 9000 | Высокий |
| Навигация (header) | 1000 | Средний |
| AI-виджет (open) | 800 | Ниже навигации |
| AI-виджет (icon) | 700 | Ниже навигации |
| Контент страницы | 1 | Базовый |

**Правило:** AI-виджет **никогда** не перекрывает навигацию, модалки и cookie-бар.

## 14. Accessibility (WCAG 2.1 AA)

| Требование | Реализация |
|-----------|------------|
| ARIA role | `role="dialog"` для open-состояния, `role="button"` для иконки |
| ARIA label | `aria-label="AI-ассистент INDAI"` |
| ARIA live | `aria-live="polite"` для новых сообщений |
| Focus management | При открытии — фокус на поле ввода; при закрытии — фокус возвращается к триггеру |
| Keyboard | `Escape` — закрытие; `Tab` — навигация внутри; `Enter` — отправка |
| Screen reader | Все элементы имеют текстовые альтернативы |
| Contrast | Минимум 4.5:1 для текста, 3:1 для интерактивных элементов |
| Touch target | Минимум 44×44px для всех интерактивных элементов (мобильные) |

## 15. Аналитические события

Все события передаются в единую систему аналитики проекта.

| Событие | Триггер | Данные |
|---------|---------|--------|
| `widget_shown` | Виджет перешёл в `icon` | `{ page, section_trigger }` |
| `widget_hint_shown` | Виджет перешёл в `hint` | `{ page, trigger_type }` |
| `widget_hint_dismissed` | Пользователь закрыл hint | `{ page, time_visible_ms }` |
| `widget_opened` | Виджет перешёл в `open` | `{ page, source: 'click' \| 'hint' }` |
| `dialog_message_sent` | Пользователь отправил сообщение | `{ page, message_index }` |
| `dialog_handoff` | Диалог завершён с исходом | `{ page, outcome_type, dialog_length }` |
| `widget_dismissed` | Пользователь закрыл виджет | `{ page, dialog_length, state_before }` |
| `widget_error` | AI-бэкенд недоступен | `{ page, error_type }` |
| `widget_fallback_contact` | Пользователь оставил контакт в fallback | `{ page }` |

**Соответствие SKILL.md § Analytics Events:** события виджета интегрируются в общую таблицу.

## 16. Критерий приёмки

Реализация AI-виджета считается корректной, если:

1. Пользователь не чувствует давления;
2. Виджет не отвлекает от HERO;
3. Диалог воспринимается как помощь, а не продажа;
4. Сайт остаётся убедительным даже при полностью выключенном AI-виджете;
5. AI-диалог логически встроен в лид-систему INDAI;
6. Все состояния из § 7 корректно реализованы и переходы работают;
7. Fallback (§ 9) работает при недоступности бэкенда;
8. Accessibility (§ 14) проходит автоматическую проверку (axe / Lighthouse ≥ 90);
9. Все аналитические события (§ 15) регистрируются;
10. Мобильное поведение (§ 4.3, § 6.1) протестировано на viewport 320–768px.

**Ключевой тест:**  
Если убрать AI-виджет, и страница теряет смысл — реализация **неверна**.
