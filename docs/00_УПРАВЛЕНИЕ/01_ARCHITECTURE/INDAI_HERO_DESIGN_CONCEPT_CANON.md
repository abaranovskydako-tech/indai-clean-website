## 2. Роль дизайна HERO

### 2.1 Назначение

Дизайн HERO в INDAI:

- подчиняется смыслу, а не украшает его
- визуализирует **управляемую промышленную мощность**
- формирует ощущение ответственности, точности и надёжности

### 2.2 Ключевое ощущение

> **Промышленная энергия находится под контролем профессионалов.**

### 2.3 Чем HERO НЕ является

HERO не продаёт.  
HERO не развлекает.  
HERO не демонстрирует эстетическую ценность как цель.

## 3. Композиционная логика

### 3.1 Базовый принцип

```
Текст — якорь.
Видео — среда.
Интерфейс — вторичен.
```

**Архитектурный тест:**  
Если убрать видео и интерфейс — HERO должен остаться сильным, понятным и убедительным.  
Если без видео HERO «разваливается» — композиция ошибочна.

### 3.2 Пространство и масштаб

| Разрешено | Запрещено |
|---|---|
| «Воздух» и крупные поля | Плотная компоновка с множеством элементов |
| Восприятие как инженерный интерфейс | Восприятие как рекламный лендинг |
| Единый фокус внимания на тексте | Дробление фокуса между элементами |
| Чистая сетка | Декоративные плашки без функции |

---

## 4. Текст: масштаб и иерархия

### 4.1 Заголовок (H1)

- Визуально **доминирует** над всеми остальными элементами HERO
- Считывается мгновенно — в первые 2 секунды
- Воспринимается как **утверждение**, а не лозунг или оффер
- Канонический текст H1 определяется в `INDAI_HERO_COPY_CANON.md`

### 4.2 Подзаголовок

- Усиливает H1, не спорит с ним
- Остаётся в одном логическом и визуальном блоке с H1
- Визуально подчинён H1 (размер, вес, контраст)

### 4.3 Типографика

| Допустимо | Запрещено |
|---|---|
| Строгое выравнивание | Креативная типографика |
| Чёткая иерархия: H1 > подзаголовок > всё остальное | Рекламные акценты (underline, highlight, gradient text) |
| Минимализм без декоративности | Визуальные «трюки» (тени, 3D, искажения) |
| Один шрифт / одна гарнитура | Множественные шрифты в HERO |

## 5. Видео и визуальная среда

### 5.1 Роль видео

Видео — **не контент, а среда присутствия**.  
Оно создаёт фон, в котором существует текст.

### 5.2 Требуемое ощущение от видео

| Должно передавать | Не должно передавать |
|---|---|
| Энергию | Хаос |
| Давление | Агрессию |
| Управляемый процесс | Неконтролируемое движение |
| Масштаб | Мелкость / детализацию |

### 5.3 Допустимые визуальные сцены

| Сцена | Статус |
|---|---|
| Водяная струя под давлением, направленная на промышленную поверхность | ✅ |
| Управляемый поток воды в контексте металлоконструкции | ✅ |
| Повторяемое, циклическое, контролируемое действие | ✅ |
| Крупный план: вода встречает металл, бетон, промышленную поверхность | ✅ |
| Общий план промышленного объекта с процессом очистки | ✅ |
| Клиповый монтаж с быстрой сменой кадров | ❌ |
| Люди крупным планом, лица, улыбки | ❌ |
| Абстрактные визуалы (частицы, волны, 3D-рендер) | ❌ |
| Визуалы, не связанные с водой / давлением / механическим воздействием | ❌ |
| Стоковое видео общего характера | ❌ |

### 5.4 Привязка к ядру

> **Запрещено** использовать визуалы, не связанные с управляемой энергией воды, давления или механического воздействия, даже если они выглядят «инженерно».

### 5.5 Обработка видео

Видео может быть:
- приглушено (desaturation)
- затемнено (overlay)
- замедлено (slow motion)

если это необходимо для **сохранения доминанты текста**.

Видео **не может** быть:
- ускорено
- зациклено с заметным «стыком» (jump cut)
- обработано фильтрами, меняющими характер содержания (tint, duotone, posterize)

### 5.6 Звук

- Видео воспроизводится **без звука** (muted) по умолчанию
- Автоматическое включение звука **запрещено**
- Кнопка включения звука **допустима**, но визуально вторична

## 6. Fallback: поведение без видео

### 6.1 Когда fallback активируется

- Видео не загрузилось (медленное соединение, ошибка CDN)
- Устройство / браузер не поддерживает autoplay
- Пользователь включил режим экономии трафика
- iOS-ограничения на autoplay в определённых контекстах

### 6.2 Канонический fallback

```
Приоритет 1: Первый кадр видео (poster frame) — статичное изображение
Приоритет 2: Отдельное фото промышленного процесса (из допустимых сцен §5.3)
Приоритет 3: Нейтральный тёмный фон (dark-500) с сохранением текстовой доминанты
```

### 6.3 Правила fallback

- Текст HERO **не должен зависеть** от видео для читаемости
- Fallback **не должен** выглядеть как ошибка или «пустая страница»
- Архитектурный тест §3.1 («убрать видео — HERO остаётся сильным») = тест fallback

## 7. Цвет и контраст

### 7.1 Принцип

> **Лучше строгая сила, чем запоминающаяся яркость.**

### 7.2 Правила

| Допустимо | Запрещено |
|---|---|
| Сдержанная палитра: тёмные тона, металл, вода | «Кричащие» цветовые решения |
| Функциональный контраст: вода / металл / структура | Декоративный контраст ради визуального эффекта |
| Ограниченное количество цветов (2–3 основных) | Градиенты как декоративный элемент |
| Overlay на видео для читаемости текста | Цветные overlay, меняющие характер видео |

### 7.3 Контраст текста на видео (accessibility)

- Текст H1 должен иметь **контраст не менее 4.5:1** относительно фона (WCAG AA)
- Для обеспечения контраста допустим полупрозрачный overlay на видео
- Контраст проверяется как на видео, так и на fallback-изображении
- Подзаголовок — контраст не менее 3:1

## 8. Интерфейсные элементы в HERO

### 8.1 Общий принцип

Любые интерактивные элементы (кнопки, AI-виджет):
- **визуально вторичны** относительно текста
- не конкурируют с H1
- не перетягивают фокус внимания

> **HERO — это смысл, а не точка клика.**

### 8.2 CTA

- Активный CTA в HERO **запрещён** (Canon: Implementation Rules §4.1)
- Допустима только нейтральная навигационная ссылка (scroll-hint, anchor)

### 8.3 AI-виджет

| Требование | Источник |
|---|---|
| Виджет статичен и видим | Implementation Rules §4.1 |
| Не инициирует диалог | Implementation Rules §4.1 |
| Не анимируется для привлечения внимания | Implementation Rules §4.1 |
| Не показывает prompt до клика | Implementation Rules §4.1 |
| Визуально вторичен относительно H1 | Данный документ §8.1 |
| Не перекрывает текст | Данный документ §8.1 |

Поведение и размещение AI-виджета дополнительно регулируется `INDAI_AI_WIDGET_PLACEMENT_CANON.md`.

## 9. Mobile

### 9.1 Общий принцип

Архитектурная роль HERO (ориентация + фильтрация) **не меняется** на mobile.

### 9.2 Требования

| Требование | Обоснование |
|---|---|
| H1 полностью виден без скролла | Первичная ориентация — приоритет (Implementation Rules §8.2) |
| Подзаголовок виден без скролла или с минимальным скроллом | Контекст не должен теряться |
| Видео: допустима замена на статичное изображение (poster frame) | iOS autoplay-ограничения, экономия трафика |
| AI-виджет не перекрывает текст | Особенно критично на малых экранах |
| Текст остаётся читаемым без зума | Минимальный размер H1 — определяется design system |
| Порядок элементов: H1 → подзаголовок → (виджет) | Не инвертируется |

### 9.3 Запрещено на mobile

- Sticky/floating CTA поверх HERO
- Автоматически выезжающие панели
- AI-виджет в полноэкранном режиме до взаимодействия
- Видео со звуком

## 10. Performance

### 10.1 Видео

| Параметр | Ограничение |
|---|---|
| Формат | MP4 (H.264) — основной; WebM (VP9) — альтернативный |
| Вес файла | ≤ 8 MB для desktop, ≤ 4 MB для mobile |
| Длительность loop | 8–20 секунд |
| Разрешение | ≤ 1920×1080 desktop, ≤ 1280×720 mobile |
| Autoplay | `autoplay muted loop playsinline` |
| Загрузка | `preload="metadata"` — не `preload="auto"` |
| Poster frame | Обязателен (`poster="..."`) — это же fallback |

### 10.2 Fallback-изображение

| Параметр | Ограничение |
|---|---|
| Формат | WebP (основной), JPEG (fallback) |
| Вес | ≤ 200 KB |
| Разрешение | Соответствует видео |

### 10.3 Текст

- H1 и подзаголовок рендерятся **до загрузки видео** (не зависят от JS)
- Шрифт HERO: `font-display: swap` или system font fallback
- Никаких layout shifts при загрузке видео (CLS = 0 для HERO-зоны)

## 11. Accessibility

### 11.1 Видео

- `aria-hidden="true"` — видео декоративное, не контентное
- Pause/play контрол видим, но визуально вторичен
- `prefers-reduced-motion: reduce` → видео заменяется на poster frame

### 11.2 Текст

- H1: семантический `<h1>`, не декоративный div с крупным шрифтом
- Контраст: §7.3 (WCAG AA minimum)

### 11.3 AI-виджет

- Доступен с клавиатуры (focusable)
- Имеет `aria-label` с описанием функции
- Не trap focus при загрузке страницы

## 12. Ощущение (качественный критерий)

### 12.1 Корректный HERO вызывает ощущение

- Управляемой мощности
- Инженерной точности
- Ответственности
- Отсутствия хаоса
- «Здесь знают, что делают»

### 12.2 Некорректный HERO вызывает ощущение

- «Красиво» → дизайн превысил роль среды
- «Эффектно» → визуал конкурирует со смыслом
- «Вау» → развлечение, не ориентация
- «Хочу кликнуть» → HERO стал конверсионным элементом
- «Как у всех» → нет инженерной идентичности

> **Если дизайн хочется «защищать словами» — он архитектурно неверен.**

## 13. Критерии приёмки (QA / Review)

### 13.1 Автоматизируемые проверки

| # | Проверка | Метод |
|---|---|---|
| A1 | H1 — семантический `<h1>` | DOM-инспекция |
| A2 | Видео: `autoplay muted loop playsinline` | Атрибуты элемента |
| A3 | Видео: `poster` атрибут присутствует | DOM-инспекция |
| A4 | Видео: вес ≤ 8 MB (desktop) / ≤ 4 MB (mobile) | Build-time проверка |
| A5 | Видео: `preload="metadata"` | Атрибуты элемента |
| A6 | Видео: `aria-hidden="true"` | DOM-инспекция |
| A7 | Нет активных CTA-кнопок в HERO | Grep по DOM |
| A8 | AI-виджет не вызывает auto-open | E2E-тест |
| A9 | Контраст H1 на фоне ≥ 4.5:1 | Lighthouse / axe |
| A10 | CLS HERO-зоны = 0 | Lighthouse |
| A11 | H1 виден без скролла на mobile (320px–428px) | Visual regression |
| A12 | `prefers-reduced-motion` → poster frame вместо видео | E2E-тест |

### 13.2 Ручные проверки (review)

| # | Проверка | Критерий прохождения |
|---|---|---|
| M1 | **Тест без видео:** убрать видео — HERO остаётся сильным? | Если нет → композиция ошибочна |
| M2 | **Тест лендинга:** можно спутать с рекламным лендингом? | Если да → дизайн некорректен |
| M3 | **Тест «вау»:** первая реакция — «эффектно/красиво»? | Если да → визуал доминирует над смыслом |
| M4 | **Тест фокуса:** глаз идёт первым на H1? | Если нет → иерархия нарушена |
| M5 | **Тест ядра:** видео связано с водой/давлением/мех. воздействием? | Если нет → нарушение §5.4 |
| M6 | **Тест клининга:** HERO можно поставить на сайт бытового клининга? | Если да → нет инженерной идентичности |
| M7 | **Тест защиты:** нужно «объяснять» дизайн? | Если да → он архитектурно неверен (§12.2) |
